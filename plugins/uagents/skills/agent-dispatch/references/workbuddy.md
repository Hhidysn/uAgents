# WorkBuddy

Use `target=workbuddy`. `model=default` remains the backend-selected text route and resolves to `route_id=workbuddy-default` with `model_resolved=null`. One concrete route is also approved: `model=deepseek-v4.1-flash`, which resolves to `route_id=workbuddy/deepseek-v4.1-flash` and is forwarded as native `--model deepseek-v4.1-flash`. `models workbuddy` reads the installed CLI help; other concrete native labels remain discovery evidence only (`configured=false`) and are not approved automatically. Do not substitute `auto` or another discovered label for an approved route.

Supported modes are `analysis` and `implementation`. Implementation opts into the native `acceptEdits` mode; analysis inherits native permissions and is not enforced read-only. The adapter locates the existing WorkBuddy `codebuddy.js`, uses `--input-format stream-json` plus stream-json output, assigns a per-task native session, disables model-created background tasks, and never bypasses approvals. For a deliberate follow-up, create a new Task with `session.continue_from_task_id=<previous-task-id>`; uAgents resolves that Task's persisted native session and invokes WorkBuddy with `--resume <session-id>` instead of assigning a new `--session-id`. To branch without mutating the source conversation, use `session.fork_from_task_id=<previous-task-id>`; this maps to `--resume <session-id> --fork-session`, and the returned native session must differ from the source session. The source Task must already be finished and use the same workspace.

Current target transport capability is `inputs.files=false`, `inputs.images=true`, and `inputs.workspace_readable=true`, with a model-specific image gate. The `workbuddy-default` route explicitly has `images=false`: real backend-selected `auto` calls rejected image-bearing request parameters. The approved `deepseek-v4.1-flash` route has `images=true`: a real native call with explicit `--model deepseek-v4.1-flash` consumed a 512×512 RGB PNG and returned the expected `RED_OK` result. Generic `input_file` content is still unsupported on WorkBuddy and remains rejected before send. Unsupported inputs are never degraded into prompt-only paths.

Probe is version-only: it does not prove login, quota, or model availability. Completion requires the matching session/cwd, one valid terminal result, no unresolved background task, and verified declared outputs. Cancellation interrupts the locally held process, but a sent task remains `indeterminate` unless remote cancellation is proven.
