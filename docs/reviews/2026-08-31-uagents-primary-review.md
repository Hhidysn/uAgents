# 主模型独立评审：uAgents 插件方案

日期：2026-08-31。此意见在启动或阅读外部候选评审前记录。

输入：`docs/superpowers/specs/2026-08-31-uagents-plugin-design.md`，初始提交 `ba10810` 中的版本。

## 初始判断

认可一个 Plugin、一个按需调度 Skill、两个独立 CDP/MCP 服务的总体边界。没有证据要求改成统一 Agent 平台或为每个 CLI 都增加 MCP。设计方向可以保留，但目前不足以直接开始完整运行时实现。

## 需要先补齐的设计问题

| 优先级 | 位置 | 问题与影响 | 建议 |
| --- | --- | --- | --- |
| P1 | 第 4.3、5、10 节 | CLI 任务要求脱离一次工具调用生存，但 runtime 的所有者、进程生存期、恢复与停止接口尚未确定；Windows job object 已是本机现实风险 | 首个阶段先验证一种 CLI 的提交/查询/取消与宿主退出行为，再决定最小监督进程方案；不先引入全 Agent 守护服务 |
| P1 | 第 5、7 节 | `mode`/`owned_paths` 是声明，实际如何证明目标可只读、能限制目录和网络尚未映射到每个适配器 | 增加能力矩阵和 fail-closed 规则；不支持的限制必须拒绝或显式缩小任务，不能无声降级 |
| P1 | 第 5、7 节 | 请求去重、窗口锁、取消只写了原则；未指定冲突键、已发送但未拿到 ID 的恢复分支和进程身份 | 写出最小状态转换、幂等冲突行为和锁失效核验；取消必须确认目标身份，不能只用可复用 PID |
| P2 | 第 3、9、10 节 | 一体插件与阶段性声明之间有小矛盾：树注释要求两个服务都就绪才有 .mcp.json，而阶段 2 单独交付 TRAE；缺应用时如何避免启动失败也不够具体 | 每阶段只声明已实现服务；MCP 初始化和目标应用可用性分开，缺应用应是工具级 unavailable |
| P2 | 第 9 节 | 状态根明确，但实际请求正文、结果与诊断日志的保存边界、保留期和容量限制未定义 | 区分默认必要结果与可选诊断；给有限保留、显式清理和活跃任务保护策略，不让插件更新触发删除 |
| P2 | 第 10 节 | 首阶段同时覆盖三个 CLI、全生命周期和插件发布，验收面偏宽 | 拆成单 CLI 垂直切片，再扩到 agy/WorkBuddy 和多模型讨论；先用虚拟 worker 验证运行时，不以真实模型费用调试进程框架 |

## 评审边界

以上是设计充分性判断，不是已复现的代码缺陷。没有运行插件或外部模型，没有修改全局配置，也没有把文档中承诺的限制当成已实现能力。保留上游实现复用优先；具体 SDK 和后台进程方案应由最小验证决定，而不是评审时凭空承诺。
