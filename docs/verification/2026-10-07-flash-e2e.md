## GLM 的恢复与格式问题

GLM 出现三项 `write` 参数错误：将 `content` 传成对象，而工具要求字符串。它在同一 Task 内改用其它方式写入文件，最终原生退出码为 1；uAgents 根据 exact session export 的完成/idle、workspace、最终消息和实际模型证据确认恢复为 succeeded，保留退出码和工具失败摘要。这些是外部 GLM 发出的工具参数问题，不是 Luna runner 下发请求错误。

GLM 的 `sources.json`、`run-summary.json` 带 UTF-8 BOM。去 BOM 后 JSON 和来源内容均可解析；直接用 Node `JSON.parse(readFileSync(...,'utf8'))` 会失败。原文件与捕获产物均保留，主代理只在证据根目录生成 `glm-sources.normalized.json`、`glm-run-summary.normalized.json` 两份无 BOM 派生副本。

实机错误还暴露原生错误字符串会回显完整工具参数。现已在诊断摘要中保留失败原因并省略 `Arguments provided`/tool/provider payload，补充回归测试，重新打包部署 alpha.2。实际三项调用使用初始 alpha.2 字节；此后的摘要裁剪更新做了确定性回归，没有为了日志变更重发模型任务。调用时与最终部署的安装哈希分别保存在 `deployment-call-build.json` 与 `deployment.json`。
