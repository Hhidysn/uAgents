# Agent dispatch

On Windows, unified MCP startup and CLI dispatch/ensure automatically register or reuse a daily TRAE/WorkBuddy check-in task when an enabled target is locally logged in. Registration is local-only; the scheduled runner independently claims daily credits. Use `checkin status` for the local task/report, `checkin --check-only` for provider observation, and `checkin disable` to persistently opt out. `UAGENTS_AUTO_CHECKIN=0` suppresses automatic registration in one process but does not stop an existing task. This workflow never sends a model prompt or a notification.

Use the `uagents` command as the primary entrypoint when the host has a local shell. This preserves the caller's environment for installed Agent CLIs. This Skill can be installed independently with `uagents skills install --dir <host-skills-directory>`; a Codex plugin is not required. If `uagents` is not on PATH, use `npm root -g` to locate the installed `uagents` package and verify its `bin/uagents.mjs` before running it with Node. Only derive a package root from this Skill's location when that directory actually contains `package.json` and `bin/uagents.mjs`; a standalone host Skill directory does not contain the CLI. Never hard-code an install path. Use the unified `uagents_*` MCP tools only when they are available and a local shell is unavailable or the user explicitly requests MCP. Both entrypoints call the same Core and can share the same state root.

Run CLI commands as `uagents <command>`. JSON is the default output. The CLI self-describes without touching runtime state: use `describe` or `describe <command>` for machine-readable command syntax, `schema request` for a single Task, and `schema council` for a first-class multi-Agent Council. Prefer these discovery commands over inferring parameter names from prose. Omit `--state-dir` to use the normal local state, or keep one explicit absolute state directory unchanged across submit and every later query. For submit/council-submit, use `--request FILE`; use `--request-stdin` only when the caller can provide stdin separately from the command text. Never place credentials or serialized requests in process arguments. For a single short Task, `run <target> (--prompt-file FILE | --prompt-stdin)` combines register, wait and result in one call and returns the same payload as `result`; it defaults to `--mode analysis` and the current directory, exits 0 only for a `succeeded` task, accepts `--observation-timeout-ms` to set the 20-minute default observation deadline (up to 60 minutes) that `--timeout-ms` does not control (a longer multi-step task otherwise ends `indeterminate` with no answer text; a durable target such as OpenCode V2 is only left unobserved at that deadline and keeps running, whereas `--execution-timeout-ms` is the deadline that actually terminates the owned process tree), and returns the last persisted status with a `run_wait_timeout`/`run_waiting_user` warning instead of guessing or resending, and returns at once with `run_not_started` when the local worker could not start the target (the task stays recoverable as `queued`/`not_sent` with `error.code = worker_start_failed`, so fix the local installation and `resume` the same task). `run -p "<prompt>"` also exists but exposes the prompt in process arguments, so prefer the file or stdin form for anything long or sensitive.

Before submitting a Task, use `schema request`; before a Council, use `schema council`. Read [references/protocol.md](references/protocol.md) for the Task protocol, [references/council.md](references/council.md) for Council lifecycle, and only the selected target references:

- [agy / Gemini](references/agy.md): explicit Gemini model, text or file work.
- [Codex CLI](references/codex.md): explicit `gpt-6-astra` and `gpt-5.6-luna` routes, text + workspace and native image input; Windows/Astra has an explicit app-server preview for cross-Task continuation/fork.
- [Claude Code CLI](references/claude-code.md): explicit Claude Code/DeepSeek gateway routes, native image/PDF/UTF-8 text inputs and native permissions, no cross-Task continuation/fork.
- [WorkBuddy](references/workbuddy.md): backend-default text route plus an approved explicit `deepseek-v4.1-flash` route. Generic file input is rejected; image input is allowed only on the explicit DeepSeek route that passed real provider E2E.
- [DeepSeek Harness](references/dsh.md): official SDK stdio JSON-RPC, explicit `deepseek-official/deepseek-flash`, one Task per SDK process, text + workspace and protocol-mapped images; real image Task remains unconfirmed. Do not substitute the Web UI label `deepseek-v4.1-flash`; the SDK route uses the API model id `deepseek-flash`.
- [OpenCode](references/opencode-council.md): explicit approved Command Code route for analysis or implementation, with declared file inputs/outputs.
- [pi](references/pi.md): native `provider/model` selector against the installed pi bundle, text + `@file`/`@image` inputs, native `--thinking` effort, and cross-Task continuation/fork.
- [Doubao Work](references/doubao-work.md): backend-default desktop Agent over a prepared loopback CDP connection.
- [TRAE CN](references/trae-cn.md): backend-default Solo Agent over the prepared local gateway.

Do not invent an unsupported target, capability, model, or fallback. Do not automatically install tools, sign in, manually approve native dialogs, buy quota, or replace a failed route. agy uses the declared native `--dangerously-skip-permissions` launch policy; review Tasks must explicitly prohibit modifications because `advisory-read-only` is prompt guidance. Send only task-relevant text and authorized files; never forward credentials or the entire conversation by default. Desktop targets are launched and managed by uAgents. Doubao Work and TRAE CN default to dedicated isolated profiles. TRAE also supports an explicit `ensure trae --profile personal` after the original window has been closed; this starts a managed CDP process using the personal configuration.

## Workflow

1. Before registering a Task, settle its target and model using `targets` when the target is unclear, `capabilities <target>` for mode, and `models <target>` for the target's default, selectable evidence, and route-level `input_support`. On the MCP fallback, use `uagents_list_targets`, `uagents_get_capabilities`, and `uagents_list_models`. These are no-prompt checks; TRAE model listing never launches a window. Follow [the model-choice conversation flow](references/model-choice.md): honor an explicit model without asking again; if the user asks to choose, show the selectors, target default, source, observation time, and relevant file/image evidence, then wait for their selection; otherwise use and briefly name a configured default, or ask when no default exists. A concrete model ID may be entered even when absent from the catalog if target policy admits passthrough. Do not treat catalog presence as proof of login, quota, or live availability. Codex, Claude Code, DSH, OpenCode, and pi expose native attachment mappings to unconfigured concrete IDs, but model acceptance remains unconfirmed until native evidence exists. Other unconfigured routes do not gain attachment capability. WorkBuddy's built-in `deepseek-v4.1-flash` route alone has verified image support. User-configured routes and defaults are loaded through CLI `--config` or `UAGENTS_CONFIG`.
2. For one Agent, create one UUID for each intentionally new Task and submit the complete versioned request. Reuse the same UUID only for the exact same effective request. For a single short Task, `uagents run <target> --prompt-file <file>` is the same protocol with register + wait + result folded into one command; it prints the same payload as `result`, so the verification and recovery rules below apply unchanged. Attachment inputs may use workspace-relative `path`, an absolute local `source`, or inline `blob:{name,data_base64}` when the host/connector already has file bytes but no useful local path. On the Unified MCP entrypoint, prefer host-facing `attachments:[{type,local_path,name?}]` when the conversation host has already materialized an upload to a local temp file; uAgents converts it to the existing blob contract, preserves the display name, and keeps the temp path out of persisted task identity. Do not manually base64 a locally materialized host attachment. `submit` normalizes external attachments into the workspace before registration. uAgents does not resolve vendor-specific connector IDs itself. To send a deliberate next turn to an already-finished WorkBuddy/OpenCode/pi conversation, still create a new UUID and use exactly one session selector: `session: { continue_from_task_id: "<previous-task-id>" }` continues the same native session, while `session: { fork_from_task_id: "<previous-task-id>" }` creates a new native branch from that context. For Codex, these selectors require Windows, `model=gpt-6-astra`, and `execution.codex_transport="app-server"` on both source and follow-up Tasks; see the target reference. Do not use the old Task UUID for the new prompt. `submit` auto-prepares the target: it discovers and verifies the local installation and, for desktop targets, starts or reuses the dedicated managed instance. Use `probe` for a read-only check that never starts anything.
3. For independent multi-Agent work, prefer Council over several unrelated submits. Use analysis/shared for review and implementation/git-worktree for parallel code candidates, then `council-diff`, optional local `council-validate`, explicit `council-adopt`, and explicit `council-cleanup` as needed. Projects may reuse named local validation standards from `.uagents/validation-profiles.json`; profile definitions come from the Council source workspace, not candidate worktrees. Council never chooses a winner, synthesizes, commits, merges, or cleans candidates in the background. Follow [references/council.md](references/council.md) for the detailed lifecycle.
4. Treat `registered`/`queued`/`starting` as local lifecycle states, not proof of native receipt. `submission=may_have_been_sent` or `status=indeterminate` forbids automatic replay or changing UUID to retry.
5. A desktop task that stops at `waiting_user` with `interaction.phase=preflight_login` means first login is required in the dedicated window. The user logs in once; then resubmitting the same UUID or calling `resume <task-id>` (MCP `uagents_resume`) resumes the same attempt. Never create a new UUID or attempt for a login wait.
6. Poll CLI `status <task-id>`, which is local and read-only. Use `result <task-id>` for response, model evidence, usage, captured artifacts, and the requested session parent. To review earlier work without contacting a provider, use `list [--target <target>] [--has-response]` for tasks and `sessions [--target <target>]` for registered conversations grouped by native session ID; neither can see a native CLI's own history, and both are scoped to one state directory. Call `reconcile <task-id>` only when explicitly checking the stored native identity/execution is appropriate; it never resubmits the original prompt. On Windows, a nonterminal OpenCode Attempt with a durable process can also use `resume <task-id>` to enter that same reconcile path. This is observation recovery, not a new OpenCode turn: only a new submit carrying `session.continue_from_task_id` or `session.fork_from_task_id` sends a new prompt based on an existing native session. Use the corresponding `uagents_*` tools only on the MCP fallback.
7. `ensure <target> [--refresh]` (MCP `uagents_ensure`) pre-warms or re-verifies a target without sending anything. CLI `ensure trae --profile personal` explicitly uses the user's existing TRAE configuration after the original window is closed. `stop <target>` (MCP `uagents_stop`) stops only the ownership-proven managed instance; it refuses user-owned windows and unknown processes.
8. For `waiting_user` after send, report the exact required native action and wait for the user. CLI `cancel <task-id>` or MCP `uagents_cancel` records cancellation intent; do not call a sent task cancelled unless the result confirms it. For durable OpenCode, cancel/observation timeout may only stop the current observer; a still-running or uncertain native process remains workspace-guarded.
9. Validate outputs against the original acceptance criteria. Native success and a plausible answer do not prove requested files or behavior are correct.

Every status/result includes `model_requested`, `model_resolved`, `model_reported`, and `model_verified`. `model_reported=null` and `model_verified=false` are valid evidence states, especially for backend-default or non-reporting targets; never fill them by inference.

`result` also returns `evidence` with existing local request/response/usage and native diagnostic or transcript paths, plus `diagnostics.native_exit_code` when known. Missing paths/codes are `null`, not proof of missing execution. agy records a bounded redacted diagnostic summary per attempt; it does not persist full tool arguments or a raw native transcript. Durable OpenCode exposes its existing stdout/stderr/exit files. Inspect `diagnostics.tool_errors` even after `succeeded`: web fetch/search failures can leave a successful native turn without the requested sources. `objective_verdict` covers the native outcome and declared output-file checks; it does not certify semantic correctness, citations, or completion of research. Output-token counts can include reasoning and tool steps rather than final answer text. Save CLI output in the caller's evidence directory when authorized, then have the primary judge the original acceptance criteria. A missing native error reason must be reported as missing; do not infer quota/auth/network from generic `ERROR`, and do not replay the task merely to obtain logs.

The MCP host may expose only explicitly declared environment variables to a plugin server. Do not interpret an MCP authentication failure as proof that the same native CLI is unusable. When local CLI execution is available, keep the request on the CLI path rather than switching entrypoints after registration.

Project wrappers may prepare a larger explicit budget and approved native permission configuration before registration. Their profile does not modify an existing Task. Inspect native_execution for the persisted process/guard snapshot, and diagnostics.native_errors/tool_errors/transcript for partial OpenCode failures even after an observation timeout; empty lists on incomplete or unattributed transcripts do not prove no tools ran.
