# Agent dispatch

Use the local `bin/uagents.mjs` CLI as the primary entrypoint when Codex has a local shell. This preserves the caller's environment for installed Agent CLIs. Derive `<plugin-root>` from this loaded Skill's location (`skills/agent-dispatch` is two levels below the plugin root); never hard-code a cache version. Use the unified `uagents_*` MCP tools only when a local shell is unavailable or the user explicitly requests MCP. Both entrypoints call the same Core and can share the same state root.

Run CLI commands as `node "<plugin-root>/bin/uagents.mjs" <command>`. JSON is the default output. The CLI self-describes without touching runtime state: use `describe` or `describe <command>` for machine-readable command syntax, `schema request` for a single Task, and `schema council` for a first-class multi-Agent Council. Prefer these discovery commands over inferring parameter names from prose. Omit `--state-dir` to use the normal local state, or keep one explicit absolute state directory unchanged across submit and every later query. For submit/council-submit, use `--request FILE`; use `--request-stdin` only when the caller can provide stdin separately from the command text. Never place prompt text, credentials, or serialized requests in process arguments.

Before submitting a Task, use `schema request`; before a Council, use `schema council`. Read [references/protocol.md](references/protocol.md) for the Task protocol, [references/council.md](references/council.md) for Council lifecycle, and only the selected target references:

- [agy / Gemini](references/agy.md): explicit Gemini model, text or file work.
- [Codex CLI](references/codex.md): explicit `gpt-6-astra` and `gpt-5.6-luna` routes, text + workspace and native image input; Windows/Astra has an explicit app-server preview for cross-Task continuation/fork.
- [Claude Code CLI](references/claude-code.md): explicit Claude Code/DeepSeek gateway routes, native image/PDF/UTF-8 text inputs and native permissions, no cross-Task continuation/fork.
- [WorkBuddy](references/workbuddy.md): backend-default text route plus an approved explicit `deepseek-v4.1-flash` route. Generic file input is rejected; image input is allowed only on the explicit DeepSeek route that passed real provider E2E.
- [DeepSeek Harness](references/dsh.md): official SDK stdio JSON-RPC, explicit `deepseek-official/deepseek-flash`, one Task per SDK process, text + workspace and protocol-mapped images; real image Task remains unconfirmed. Do not substitute the Web UI label `deepseek-v4.1-flash`; the SDK route uses the API model id `deepseek-flash`.
- [OpenCode](references/opencode-council.md): explicit approved Command Code route for analysis or implementation, with declared file inputs/outputs.
- [Doubao Work](references/doubao-work.md): backend-default desktop Agent over a prepared loopback CDP connection.
- [TRAE CN](references/trae-cn.md): backend-default Solo Agent over the prepared local gateway.

Do not invent an unsupported target, capability, model, or fallback. Do not automatically install tools, sign in, approve native dialogs, buy quota, or replace a failed route. Send only task-relevant text and authorized files; never forward credentials or the entire conversation by default. Desktop targets are launched and managed by uAgents. Doubao Work and TRAE CN default to dedicated isolated profiles. TRAE also supports an explicit `ensure trae --profile personal` after the original window has been closed; this starts a managed CDP process using the personal configuration.

## Workflow

1. Before registering a Task, settle its target and model using `targets` when the target is unclear, `capabilities <target>` for required inputs/mode, and `models <target>` for the target's default and selectable evidence. On the MCP fallback, use `uagents_list_targets`, `uagents_get_capabilities`, and `uagents_list_models`. These are no-prompt checks; TRAE model listing never launches a window. Follow [the model-choice conversation flow](references/model-choice.md): honor an explicit model without asking again; if the user asks to choose, show the selectors, target default, source and observation time, then wait for their selection; otherwise use and briefly name a configured default, or ask when no default exists. A concrete model ID may be entered even when absent from the catalog if target policy admits passthrough. Do not treat catalog presence as proof of login, quota, or live availability. Unconfigured concrete models have text + workspace capability only. WorkBuddy's built-in `deepseek-v4.1-flash` route alone has verified image support. User-configured routes and defaults are loaded through CLI `--config` or `UAGENTS_CONFIG`.
2. For one Agent, create one UUID for each intentionally new Task and submit the complete versioned request. Reuse the same UUID only for the exact same effective request. Attachment inputs may use workspace-relative `path`, an absolute local `source`, or inline `blob:{name,data_base64}` when the host/connector already has file bytes but no useful local path. On the Unified MCP entrypoint, prefer host-facing `attachments:[{type,local_path,name?}]` when the conversation host has already materialized an upload to a local temp file; uAgents converts it to the existing blob contract, preserves the display name, and keeps the temp path out of persisted task identity. Do not manually base64 a locally materialized host attachment. `submit` normalizes external attachments into the workspace before registration. uAgents does not resolve vendor-specific connector IDs itself. To send a deliberate next turn to an already-finished WorkBuddy/OpenCode conversation, still create a new UUID and use exactly one session selector: `session: { continue_from_task_id: "<previous-task-id>" }` continues the same native session, while `session: { fork_from_task_id: "<previous-task-id>" }` creates a new native branch from that context. For Codex, these selectors require Windows, `model=gpt-6-astra`, and `execution.codex_transport="app-server"` on both source and follow-up Tasks; see the target reference. Do not use the old Task UUID for the new prompt. `submit` auto-prepares the target: it discovers and verifies the local installation and, for desktop targets, starts or reuses the dedicated managed instance. Use `probe` for a read-only check that never starts anything.
3. For independent multi-Agent work, prefer Council over several unrelated submits. Use analysis/shared for review and implementation/git-worktree for parallel code candidates, then `council-diff`, optional local `council-validate`, explicit `council-adopt`, and explicit `council-cleanup` as needed. Projects may reuse named local validation standards from `.uagents/validation-profiles.json`; profile definitions come from the Council source workspace, not candidate worktrees. Council never chooses a winner, synthesizes, commits, merges, or cleans candidates in the background. Follow [references/council.md](references/council.md) for the detailed lifecycle.
4. Treat `registered`/`queued`/`starting` as local lifecycle states, not proof of native receipt. `submission=may_have_been_sent` or `status=indeterminate` forbids automatic replay or changing UUID to retry.
5. A desktop task that stops at `waiting_user` with `interaction.phase=preflight_login` means first login is required in the dedicated window. The user logs in once; then resubmitting the same UUID or calling `resume <task-id>` (MCP `uagents_resume`) resumes the same attempt. Never create a new UUID or attempt for a login wait.
6. Poll CLI `status <task-id>`, which is local and read-only. Use `result <task-id>` for response, model evidence, usage, captured artifacts, and the requested session parent. Call `reconcile <task-id>` only when explicitly checking the stored native identity/execution is appropriate; it never resubmits the original prompt. On Windows, a nonterminal OpenCode Attempt with a durable process can also use `resume <task-id>` to enter that same reconcile path. This is observation recovery, not a new OpenCode turn: only a new submit carrying `session.continue_from_task_id` or `session.fork_from_task_id` sends a new prompt based on an existing native session. Use the corresponding `uagents_*` tools only on the MCP fallback.
7. `ensure <target> [--refresh]` (MCP `uagents_ensure`) pre-warms or re-verifies a target without sending anything. CLI `ensure trae --profile personal` explicitly uses the user's existing TRAE configuration after the original window is closed. `stop <target>` (MCP `uagents_stop`) stops only the ownership-proven managed instance; it refuses user-owned windows and unknown processes.
8. For `waiting_user` after send, report the exact required native action and wait for the user. CLI `cancel <task-id>` or MCP `uagents_cancel` records cancellation intent; do not call a sent task cancelled unless the result confirms it. For durable OpenCode, cancel/observation timeout may only stop the current observer; a still-running or uncertain native process remains workspace-guarded.
9. Validate outputs against the original acceptance criteria. Native success and a plausible answer do not prove requested files or behavior are correct.

Every status/result includes `model_requested`, `model_resolved`, `model_reported`, and `model_verified`. `model_reported=null` and `model_verified=false` are valid evidence states, especially for backend-default or non-reporting targets; never fill them by inference.

The MCP host may expose only explicitly declared environment variables to a plugin server. Do not interpret an MCP authentication failure as proof that the same native CLI is unusable. When local CLI execution is available, keep the request on the CLI path rather than switching entrypoints after registration.
