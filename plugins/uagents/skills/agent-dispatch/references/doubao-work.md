# 豆包工作：本地桌面任务

只在选择豆包工作时读取。当前适配版本针对 Windows DoubaoWork 2.27.6、Chromium 147 的实测页面契约；升级客户端后先运行 `doubao_probe`。

## 环境边界

用户需自行以 `--remote-debugging-address=127.0.0.1 --remote-debugging-port=9222` 启动豆包工作。插件只连接，不启动、结束或重启应用。CDP 端口让本机进程能够控制登录中的窗口；不要绑定非回环地址，用完后正常退出该实例。

`doubao_probe` 只验证版本和唯一聊天 target，不发送任务、不核验余额。连接失败时说明准备要求，不自动安装、登录或切换付费路线。

## 调用步骤

1. 为每个有意的新任务生成 UUID，保留清楚的交付标准。只传任务必需文本，不传整个聊天历史、密钥或认证文件。
2. 调用 `doubao_submit`，传 `request_id`、`prompt` 和可选 `timeout_ms`。它会取得跨进程窗口锁、导航到空白任务页并在确认原生会话 ID 后返回。任务发送后异常不自动换 UUID 重试。
3. 用同一 UUID 调用 `doubao_status`。`running` 继续有界查询；`needs_user` 让用户在豆包窗口处理审批，再查询同一任务；`unknown` 保留窗口和会话证据，不自动重放。
4. 终态后用 `doubao_result` 取回回复和完成证据。适配器只读取本任务用户消息之后的新回复，并要求原生会话 URL、稳定回复和完成控件一致。

当前没有公开 `cancel`：停止生成的可靠控件和远端确认语义尚未真实验证。不要通过关闭 CDP、结束进程或导航离开页面冒充取消成功。文件/电脑操作沿用豆包的“按需确认”权限，适配器不自动批准。

同一受控窗口串行执行，不同 Codex 进程共享插件数据目录中的窗口锁。成功终态会释放锁；结果归属不明或超时后保留锁，避免下一个任务覆盖仍可能运行的会话。当前 alpha 没有自动清理或强制解锁工具。
