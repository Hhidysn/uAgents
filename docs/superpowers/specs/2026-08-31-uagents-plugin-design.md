# uAgents 插件设计

日期：2026-08-31。状态：目标设计与首轮实施修订。用户已授权 CLI 验证和 agy 最小切片，并明确取消强制只读要求。仓库已有原生权限预览源码；agy 使用现有权限和单次文件修改模式。完整 CLI/MCP 阶段及安装均未完成。最新证据见[实施记录](../../verification/2026-08-31-cli-runtime.md)。

## 1. 目标、范围和成功标准

Codex 是主力开发者和编排入口。用户希望在 Codex 实际决定委派时，才读取目标 Agent 的具体调用方式，减少常驻指令的长度，并复用现有订阅、每日积分和 OpenCode 模型路线。

| 用途 | 接入对象 | 第一选择 |
| --- | --- | --- |
| 前端、UI、美术方向、视觉评审 | agy 中的 Gemini | 已有 CLI；模型及图片能力在调用时核验 |
| 合适的脚本修复、小范围编码、测试和文档 | WorkBuddy、TRAE | WorkBuddy 内嵌 CLI；TRAE 的现有 CDP/MCP 桥接 |
| 多模型独立提案、讨论、思维风暴 | OpenCode 已配置模型 | 新建相互独立的 CLI 会话 |
| 豆包工作的桌面 Agent 能力 | 豆包工作 | 单独的 CDP/MCP 桥接 |

设计验收标准：

1. 一个 Codex 插件安装单元包含一个调度 Skill，以及两个独立的 MCP 服务配置和可执行产物；具体阶段只声明已实现的组件。
2. 只调用 agy 时，不读取 WorkBuddy、TRAE、豆包或多模型讨论的完整说明。
3. 每个任务能明确关联调用方、目标路线、原生会话/任务 ID、工作目录、结果和产物，不能把其他会话或 UI 文本当成答案。
4. 长任务不依赖主模型一直阻塞在一次工具调用中；能够查询、跟进、处理审批、取消和无法确认的执行状态。
5. 安装、环境准备、执行任务分开；安装不会自动启动桌面应用、开启 CDP、发送模型请求或修改全局路由。
6. 新机器在完成显式环境准备后可以运行，发行版不依赖本机 `third-part-research/` 或原来的绝对源码路径。

当前实施已推进到三个 CLI 的基础切片：agy/WorkBuddy 文件任务、OpenCode 独立文本提案；验证结果见[CLI 接入记录](../../verification/2026-08-31-cli-adapters.md)。非目标包括双向 Agent 通信平台、自动消耗每日额度的定时任务、统一聊天 UI、云端控制桌面、多租户任务服务、修改供应商登录或绕过权限。

## 2. 方案比较和决定

| 方案 | 收益 | 代价 | 结论 |
| --- | --- | --- | --- |
| 普通 Skill 仓库，附 MCP 源码和安装脚本 | 最少包装，容易直接阅读 | Skill 安装不保证 MCP 注册；升级、依赖、路径需要额外处理 | 适合原型，不作为最终一体安装方式 |
| 一个 Plugin，包含一个 Skill 和两个 MCP | 一次分发；CLI 保持直接；两个桌面应用分别维护 | 需管理插件打包和各 MCP 生命周期 | 采用 |
| 一个统一 MCP 包装全部 Agent | 单一工具入口 | 额外引入调度服务，把成熟 CLI 也重新包装；故障面和维护范围扩大 | 当前不采用 |

“两个 MCP”是两个服务，不是只能有两个工具函数，也不要求它们属于两个独立仓库。CDP 是它们内部控制应用的实现手段，MCP 是向 Codex 暴露能力的接口。

## 3. 仓库与发布边界

工作仓库保留用户指定的 `uAgents` 目录名；计划把实际插件根放到 `plugins/uagents/`，使插件目录名与 manifest 名 `uagents` 一致，也避免把研究资料带进安装包。

以下是完整目标结构；没有实现的目标不生成占位服务或清单。当前代码和运行机制放在 Skill 的 scripts 内，保持组件自包含：

```text
uAgents/
├─ README.md
├─ .gitignore
├─ docs/
│  ├─ research-index.md
│  └─ superpowers/specs/2026-08-31-uagents-plugin-design.md
├─ third-part-research/             # 本机归档；Git 忽略，不发布
└─ plugins/uagents/                 # 未来插件发行根
   ├─ .codex-plugin/plugin.json
   ├─ .mcp.json                     # 首个服务就绪后只声明它；当前不创建
   ├─ skills/agent-dispatch/
   │  ├─ SKILL.md
   │  ├─ references/
   │  │  ├─ agy.md
   │  │  ├─ workbuddy.md
   │  │  ├─ opencode-council.md
   │  │  ├─ trae.md
   │  │  └─ doubao-work.md
   │  └─ scripts/                  # agent-call、task、store、worker、cli-adapters；相对发行位置定位
   ├─ servers/trae/                 # 保持独立启动与版本记录
   ├─ servers/doubao-work/
   └─ THIRD_PARTY_NOTICES.md        # 实际引入第三方代码后添加
```

发行包采用显式文件清单。不得包含研究归档、嵌套 `.git`、真实提示词日志、账号信息、个人路径配置、临时截图和开发缓存。依赖安装使用固定版本/锁文件；平台运行时先检查再准备，不能仅靠安装一个 Skill 假定 Node 或桌面应用已经存在。

当前 skills-only 预览 manifest 为 0.1.0-alpha.3；不创建 MCP 配置或个人市场条目，不自动安装。manifest 和 Skill 格式校验与真实目标能力验收分别报告。

## 4. 按需加载与职责

### 4.1 全局规则

全局 `AGENTS.md` 由用户管理，本轮保持不变。未来若用户批准精简，只保留角色分工、模型/额度偏好、权限边界和“实际委派前读取 agent-dispatch”的短入口；不要复制全部命令、CLI 帮助和历史排错记录。

插件不能在安装时自动改写这个文件。插件内的通用流程不能覆盖用户显式选择的主模型、供应商或审批设置。

### 4.2 一个调度 Skill

Skill 名称：`agent-dispatch`。描述应使它在“执行外部 Agent 委派或多模型讨论”时被选中，而不是一看到“前端”就接管所有开发，也不能把仅讨论调用架构当成执行授权。

SKILL.md 只包含：适用边界、参数交接、对应参考文件入口、调用与跟进流程、回收结果的条件。正文以能一次读懂为目标，不堆完整工具 schema、安装手册或长错误码表。

按需读取顺序：名称和描述 → SKILL.md → 当前目标的一个参考文件。若调用失败，才进一步读取该目标的恢复章节。脚本可执行时直接执行，不要求每次把实现全文载入模型上下文。

各参考文件只记录非显而易见的差异：

- `agy.md`：项目选择、实际可用模型、图像输入/输出能力、多轮会话、CLI 超时；输出美术建议不等于生成了图片文件。
- `workbuddy.md`：内嵌入口发现、JSON 结果形状、工具限制、审批状态、原生 session ID；不得默认加 `-y`。
- `opencode-council.md`：显式 provider/model、独立上下文、共同题目和评价维度、分歧讨论与综合；`--pure` 仅禁用外部插件，不等同于只读。
- `trae.md`：现有 MCP 的准确工具映射、窗口归属、任务 ID、Windows 适配与结果证据；不另造同名伪兼容契约。
- `doubao-work.md`：对应 MCP 工具、受控窗口/会话、哪些状态需要用户处理、尚不支持的动作。

暂不拆独立的 council Skill：目前它是委派的一种模式。只有未来需要独立触发、维护和发布时再拆。

### 4.3 脚本和服务

CLI 脚本负责可确定的执行细节：输入校验、参数数组构造、进程启动、原生输出解析、明确会话续接、超时、取消以及输出文件位置。使用 Node 标准库处理文件、进程和 JSON；不要让模型每次拼接不可靠的 PowerShell 命令。

两个 MCP 分别负责各自应用的 CDP 连接、页面定位、任务所有权与生命周期。MCP 注册、进程启动、工具描述加载、实际连接桌面应用是不同阶段；不能承诺安装后所有工具说明都由宿主延迟加载。实现可保证的是：参考文档按需读取，服务初始化不主动发任务或重启应用。

MCP 元数据保持简洁。优先面向任务暴露接口，不把任意 CDP 脚本执行、读取所有对话或自动批准所有弹窗作为通用工具。

## 5. 调用契约

不要求改造所有原生服务为同一协议；在结果整理层使用共同字段，保留原生字段和能力差异。

| 输入字段 | 含义 |
| --- | --- |
| `request_id` | 调用方生成的请求标识，用于去重、追踪和安全恢复 |
| `target` / `model` | 指定应用与模型路线；不能在失败后静默更换供应商或计费路线 |
| `prompt` / `context_files` | 最小必要任务说明和已授权文件，不传整个聊天历史或秘密 |
| `workspace` / `owned_paths` | 绝对工作目录与允许修改范围 |
| `mode` | `analysis` 或 `implementation`；表达任务意图，不代表硬性只读 |
| `permission_policy` / `expected_outputs` | 当前均使用 native；agy/WorkBuddy implementation 单次启用原生文件修改模式，并验收相对产物路径 |
| `timeout` | 截止条件；超时后还要区分本地等待停止与远端任务停止 |
| `acceptance` | 能够检查的交付标准 |
| `session_id` | 仅在明确续接某一任务时传入；默认创建独立会话 |

共同输出包括：本地任务 ID、原生 task/session ID、状态、实际路线/模型（未知则标明未知）、结果摘要、产物路径、验证证据、结构化错误和下一步操作。记录目录不写入插件安装缓存。

状态至少覆盖：排队、运行中、需要用户处理、成功、失败、请求取消、已取消、执行状态未知。未知是需要核对的状态，不是“失败所以可安全重试”。遇到发送后断线、取消未确认或结果采集无法可靠归属时，保留任务标识并进入未知/待核对状态。

提交与跟进分离：长任务返回任务 ID，后续通过查询或宿主支持的事件跟进。CLI worker 的进程生命期不能依赖某次短暂工具调用；Windows 需要验证宿主退出和 job object 是否会连带杀掉子进程。这个问题属于 CLI 阶段的验收项，不能靠“启动后台进程”一句话假定解决。

需要跨进程保存的任务记录采用原子更新和明确文件/窗口所有权。取消只针对本插件确认持有的进程或会话，不能按进程名批量终止其他任务。非持久原生会话在插件重启后不得伪造恢复成功。

## 6. 多模型讨论流程

1. Codex 在阅读外部意见前记录自己的方案及关键假设。
2. 为选定模型生成相同的题目、约束、证据和输出要求，各自新建会话。默认不召集所有模型。
3. 收集观点、理由、风险、证据和不确定性；未返回的参与者明确标注。
4. 只有重大分歧未解决时，再做一轮有边界的讨论。独立提案阶段不互相展示答案。
5. Codex 按证据综合；不按票数替代判断，不自动把评审建议写入项目。

沿用用户已有的模型授权和额度规则。指定了 agy 的 Gemini 就不自动改成 OpenCode 的 Gemini；每日积分未知不当作无限免费。普通执行 worker 不继续委派；指定的 council 调度助手仅启动 Codex 明确选定的参与者，不自行扩张。

## 7. CDP 连接与桌面任务边界

TRAE 与豆包使用不同端口和明确的应用/窗口标识，不能因都支持 CDP 就共享一个会话。每个受控窗口串行执行；在多 Codex 会话同时连接时，窗口占用锁需要跨进程有效。不能只使用各 MCP 进程内的布尔变量。

优先连接用户已授权的受控窗口。没有 CDP 端口时返回可操作的环境准备提示，不自动强退用户应用来重启。接口只绑定回环地址；回环绑定不代表本机其他进程无法访问，因此仍需令牌/来源与接口暴露评估。

任务提交前记录目标会话、提交边界与新消息标识。必须将“输入成功”“发送成功”“任务结束”“答案完整采集”分开判断。旧答案、工具栏、按钮文案或整个面板文本不能直接成为结果。

审批、登录、信任工作区等状态返回需要用户处理，不能默认点击批准。analysis 本身不强制只读；只有用户明确要求硬性限制而适配器无法保证时，才拒绝这项不受支持的要求。用户已允许写入时使用对应原生执行能力，不额外施加零工具准入。

不提取账号令牌，不复用反编译的专有代码，不调用未经文档化的内部服务来绕过既有权限。保留用户原有登录方式。

## 8. 复用与依赖选择

| 能力 | 优先选择 | 验证要求 |
| --- | --- | --- |
| agy / WorkBuddy / OpenCode 调用 | 已安装 CLI、原生 session 和结构化输出 | 以本机帮助与小范围集成验证为准；不把历史清单当兼容性保证 |
| 基础文件、JSON、进程操作 | Node 标准库 | 正确处理 Windows 路径、参数、取消和进程生命周期 |
| TRAE 桥接 | 现有 TRAECNclaw 的实现和契约 | 核实来源与许可证，提取必要补丁，保留上游通知，验证 Windows |
| 新的豆包 MCP 协议层 | 官方维护的 MCP SDK | 实现前核对确切版本、许可证、Node 支持和集成成本；本轮不下载 |
| 豆包 UI 自动化 | 受控 CDP 页面操作与最小应用适配 | 使用合法可用的源码/接口，不复制私有应用内部实现 |

尚未确认具体 MCP SDK 版本，因此本文不声称依赖已经选型或锁定。实现前需要记录选用版本和来源；不为完成文档而编造版本号。

现有 TRAECNclaw 的本地工作区包含重要未提交内容，不能直接作为“干净 v0.6.0 上游”发布。README、package 元数据、Git HEAD 与本地许可证的来源记录见资料索引。

## 9. 安装、配置和状态存储

用户可从个人或仓库市场安装一个 Plugin；市场注册是单独的显式动作，不随本轮设计执行。普通 Skill 安装不保证 MCP 自动注册；插件发行包声明已存在的 Skill、MCP 配置与运行入口。

建议本机状态根为 `%LOCALAPPDATA%\uAgents`，允许用户显式选择其他绝对路径；当前脚本要求传入展开后的 `--state-dir`，不自动挑选位置。个人路径/路由配置和任务记录放这里，插件目录只放发行内容。若数据根不可写，应报错，不静默把数据写到工作项目、研究目录或其他盘。

配置引用供应商既有登录状态，不复制账号凭据。对于确需独立认证的本地 MCP，走专用秘密存储或运行环境注入，不写入仓库和日志。日志默认记录操作元数据，不完整保存 prompt、图片和模型输出；用户要求诊断时再明确范围。

环境检查分应用返回可用状态：未安装豆包不能阻断 agy。安装/更新只准备插件文件和连接声明，不能自动清理任务数据、改全局 AGENTS.md、登录账号、开启 CDP 或发送收费测试任务。

第一版只支持本机 Windows + Codex。Skill 中不硬编码当前用户名或安装后的插件缓存绝对路径。桌面 CLI 路径允许自动发现并人工配置覆盖，发现失败时准确报告。

## 10. 分阶段交付与验收

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| 0：设计与会审 | 仓库、资料归档、设计与评审文档 | 已完成整理和会审；用户已授权推进首个切片 |
| 1a：运行验证与 agy | 模拟 worker、一个 Skill、agy 原生权限入口、产物验收、skills-only 预览包 | 运行机制测试与格式检查；真实 agy 完成指定目录内的可归属任务并检查产物；证据见实施记录 |
| 1b：其余 CLI | WorkBuddy 与 OpenCode 适配，扩展 agy 已证实能力 | 基础验收已通过：WorkBuddy 文件落盘与回收、OpenCode DPF/GLM 同题独立返回；原生后台及自动恢复不扩大承诺 |
| 2：TRAE | 接入现有 MCP、可分发依赖/补丁与来源记录 | Windows 下任务提交→完成→提取答案可靠；遇到审批会停下；窗口串行和重复提交保护有效 |
| 3：豆包工作 | 独立 MCP 和配套参考文件 | 从历史“输入框能写字”推进到真实完整任务闭环；旧回复不串入结果；无法确认取消时正确报告未知状态 |
| 4：一体分发 | Skill + 两个 MCP 的完整 Plugin | 干净安装路径验证；归档缺席仍可运行；缺一个应用不拖垮其余组件；更新不丢本机配置或任务记录 |

测试关注行为，不围绕文档措辞写测试：路径含空格/中文、CLI JSON 错误事件、同一请求重复提交、进程退出、提交后断线、取消竞态、多个调用者争用同一窗口、审批等待、插件重启后的任务识别。

真实 GUI/模型验收使用用户授权的目标与任务范围；不发送请求来试探余额，也不以 `total_cost_usd: 0` 证明免费额度。运行失败、需要审批及已完成均记录原生状态；不把 CLI 零退出或成功回复当成产物验收。

## 11. 设计自审

- 安装包数量与 MCP 工具数量分开描述；两个桌面服务不强制统一改造上游契约。
- Skill 只负责委派流程，Codex 保持主控；引用既有个人路由而非私自更新全局规则。
- 按需读取参考文件与 MCP 宿主何时加载工具 schema 分开，不作未经验证的延迟加载承诺。
- 日志、配置、运行状态与发行内容分开；历史研究不作为默认运行依赖。
- 豆包完整调用闭环、Windows 子进程生存期、TRAE Windows 适配明确列入验收，没有标为已完成。
- 用户已授权首个切片与文件写入；预览代码、模拟通过和真实调用分开记录，不因 agy 跑通而声称所有 CLI 或两个 MCP 已完成。

## 11.1 首个切片的具体约束

- agy 接受已授权文本及专用目录内文件产出；不接受 workspace/context_files/owned_paths/session_id。默认原生 Agent，implementation 单次启用 accept-edits，analysis 继承原生模式；不改全局设置或加全工具审批跳过参数。sandbox 只用于原生终端限制，不宣称硬性只读。
- 进程 cwd 与 Agent 的活动目录不等价。通过 --add-dir 及带绝对路径的任务前缀传递目录；implementation 必须声明 expected_outputs。成功后检查预期文件真实位置、非空、大小及摘要；缺少产物时保留原生 SUCCESS，但插件标记 failed。该检查不能阻止越界写入，也不能替代人工或浏览器功能验收。
- 每个任务一个 Node worker，采用标准库 detached、独立 stdio 与 unref。本机已验证提交工具退出后完成；未验证 Codex 退出或系统重启，15 秒心跳过期按未知处理，不自动拉起重跑。
- 使用 UUID 独占任务目录与规范化有效输入摘要去重，同 ID 不同内容冲突；先保存发送意图再写 stdin。发送后中断不自动重发，即使请求状态未知。
- 取消通过任务目录内的控制标记交给持有 ChildProcess 的 worker，避免根据保存的 PID 去结束其他进程；缺少原生确认时不宣称远端已取消。
- 当前保存必要结果与状态，临时 inbox 在 worker 读取后删除；调用方原请求文件及异常留下的 inbox 不自动删除。无自动清理与保留期管理，暂不面向多用户或不可信本机进程。
- WorkBuddy 原生 --bg 已实测返回启动信息，但稍后 logs 找不到会话且专属日志为空，未形成可靠闭环。因此当前选择单次 print + stream-json，复用已有 worker；不把“有原生命令”当成已验证生命周期。OpenCode run 内置进程内服务与原生 session，直接消费其 JSON 流，无需额外 serve 守护进程。

## 11.2 其余 CLI 的实际契约

- WorkBuddy 接入现有安装里的 codebuddy.js；workbuddy-default 表示不覆盖既有默认模型，本次报告 auto，具体底层模型与免费额度未知。显式 UUID 传 --session-id，匹配 init cwd 与终态 result；单次使用 acceptEdits 时不跳过命令审批。
- OpenCode 当前只接受 DPF/GLM-5.2 两条常用路线的 analysis。每次独立 run --pure --format json，不自动续接或自动审批。按照 sessionID/part/messageID 关联结果，最后 stop + 对应文本 + 正常退出才成功；model_reported=null 明确标记流不回显实际模型。
- 两种 CLI 都需要先送入 stdin 再拿原生事件，不能套用 agy 的发送前身份门禁；先落盘可能已发送状态，再做事后归属检查，异常按 unknown，不自动重发。
- 两个模型的会审由 Codex/已有调度助手执行逐任务提交与结果综合。共用 brief，独立 UUID/session，先记主线程方案；当前不引入自动多轮争论服务或共享会话。
