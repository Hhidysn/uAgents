# pi CLI 接入

## 范围

新增 `pi` target：以 `@earendil-works/pi-coding-agent` 的 `dist/bundle/cli.js` 为原生入口，由当前 Node 运行 `--mode json` JSONL 事件流。覆盖 analysis / implementation、文件与图片附件、`--session` 续接、`--fork` 分叉、`--list-models` 模型目录和 `--thinking` effort 映射。

## 构建与运行环境

- 工作树：`8eb2104` 加本记录对应的未提交改动（含同期 OpenCode catalog 提交）；`plugins/uagents/mcp/unified/dist/*` 由 `node scripts/build.mjs` 重建。
- Node `v24.13.0`；pi `1.0.4`；Windows。
- 安装身份：`models pi` 经 Host installation 校验后调用原生 `--list-models`。

## 未验证与限制

- 同一文件附件路线在 `antigravity/gemini-3-8-flash` 上使 pi 的 antigravity bridge 崩溃（stderr `agy exited with status 143`），任务最终为 `indeterminate/deadline_remote_state_unknown`；这是原生 provider bridge 行为，非 uAgents 映射问题。附件可用性仍依赖具体 provider。
- `models pi` 的逐路线 `input_support` 目前为 `unmapped`（registry 证据层未登记 pi 的附件映射）；上表只证明已测路线。
- `native_args` 未开放；`execution_timeout_ms` 不支持（无持久进程观察）；取消、审批等待、非 Windows 平台与其它 pi 版本未逐项实机验证。
- usage 中 cost 为 0 是 provider 未报告价格，不代表免费。

## 交叉审查与加固

由只读 `reviewer` 子代理（`openai/gpt-6.1-sol`，thinking high）检视全部未提交变更，提出 4 项发现。逐项复核后：

| 发现 | 结论 | 处理 |
| --- | --- | --- |
| session header 若滞后出现，之前的 assistant 事件仍被认证 | 成立（`docs/json.md` 明确 header 为首条记录） | 解析器要求 header 先行、只允许一个 header，且先校验 workspace 再发布 session 身份 |
| `agent_settled` 后新的 `agent_start` 仍沿用旧 settlement | 成立（`agent_start`/`agent_end` 为低层 run 边界） | `agent_start` 清除 settlement，终态需最新 run 的 settlement |
| `--list-models` 空目录时把 `No models available.` 解析为 `No/models` | 成立（`dist/cli/list-models.js` 空目录只打印提示） | 无 `provider model` 表头即返回空 catalog |
| `UAGENTS_PI_BIN` 未接入 Host installation 发现 | 成立但非本 target 引入 | 未改：与 `UAGENTS_OPENCODE_BIN`、`UAGENTS_CLAUDE_CODE_CLI` 同构。执行路径在无 Host 安装时仍由 `locateCli(target, process.env, null)` 回退到该 env；只有 `models <target>` 的 `resolveInstallation` 需要可被 Host 校验的安装。记为已知限制 |

审查同时确认无问题：prompt 仅走 stdin（argv 无 prompt）、`process.execPath` + 参数数组无 shell、effort 由协议限制并获 pi 自身截断、嵌套 `provider/model` 首斜杠切分、Host 校验与缓存键、contract/policy 拒绝 `native_args` 与 `execution_timeout_ms`。

## 最终修复复核

上述 Provider 实测对应会话守卫加入前的构建。最终修复提交加入以下约束并完成定向验证：

- 最终 assistant 必须同时匹配请求的 provider 与 model；同名不同 provider 会失败，`model_verified=false`，不丢失实际模型自报。
- driver 强制显式加载包内 `pi-session-guard.mjs`，保留用户扩展和原生权限。通过受支持的扩展上下文 API 在执行中 new/resume/fork/tree 的操作被取消，结果保留 `indeterminate/native_session_change_blocked`。初始 `--session` / `--fork` 参数仍开放。
- JSON 模式会把普通扩展 stdout 改送 stderr，守卫使用 fd 1 输出有限的身份记录。守卫记录先于异步 session header 是真实顺序，解析器允许此控制记录先行，并核对相同 session/cwd；普通事件仍不能先于 header。
- 启动、settlement 及退出时核对身份；成功必须有退出（quit）身份确认。fd 1 的控制记录可越过原生异步 JSON 队列，所以已排队的 agent_start 不撤销 quit 这一进程生命周期证据；已补交错顺序回归。缺失结束证据不确认成功。扩展 reload 失效旧守卫证据；新 agent run 清理旧正文和模型证据。会话完整性错误优先于审批等待。
- 守卫输出失败时，取消钩子仍返回 `cancel:true`。它不是恶意同进程 JavaScript 的隔离边界；任意扩展仍具有原生进程权限。
- 模型目录保留原生 ID，包括 `~`、`@` 与长 ID，不自行限制模型字符；提交准入仍遵循既有显式禁用及协议格式策略。
